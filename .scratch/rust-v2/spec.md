# agy-pulse v2.0.0：单一原生 Rust 二进制重写规格书

Status: ready-for-agent

## Problem Statement

当前版本的本地运行时完全基于脚本语言构建，在实际使用与维护中面临四项核心痛点：

1. **高频调用下的冷启动延迟与环境脆弱性**：宿主在每次模型步骤完成后都会启动一次外部子进程刷新**状态栏**。现行脚本运行时仅空载启动即耗时上百毫秒，叠加数据库模块加载与多次外部命令调用后延迟显著；同时强依赖用户本机预装高版本脚本运行时（缺少内置数据库支持时还会退化为低效全量文本读写），在跨平台搜寻可执行文件、探测终端编码与调用系统工具时脆弱易损。
2. **场外请求引发的账号合规与封禁隐患**：旧版“云端配额”功能会在宿主外部提取用户系统密码箱或本地登录凭据，并伪装客户端身份直接请求服务端私有接口，存在违反服务条款（ToS）导致反重力账号被风控封禁的风险。
3. **计费口径分裂与概念混乱**：同一套字数与美金计费逻辑散落在多处，导致同一场对话在**状态栏**显示的汇总金额与**网页看板**归档的**账本**金额因系统提示词、缓存字数算法不一致而互相打架；同时旧实现对**单窗对话**与**任务树**概念混用，多模块职责纠缠，维护成本高。
4. **网页看板后台断连体验不佳**：由于旧后台常驻内存占用较高，当用户将**网页看板**窗口最小化或切到后台标签页满 10 分钟后，前端便停止心跳导致后台服务自行退出，用户切回页面时连接断开，不得不返回终端重新执行命令打开。

## Solution

在 `v2.0.0` 中，使用单一原生静态编译的 Rust 二进制全面接管本地运行时与全部命令行功能，彻底移除脚本运行时与包管理器依赖：

1. **毫秒级原生单二进制与五端预编译分发**：将**状态栏**渲染、宿主数据摄取、SQLite **账本**、交互式配置向导、本地**网页看板**服务端、安装卸载器及版本自更新收敛进单个原生可执行文件。面向五大主流平台（Windows x64、macOS Apple Silicon 与 Intel、Linux x64 与 ARM64 免依赖静态版）通过 GitHub Releases 配合一键引导脚本与源码安装分发，保留宿主所需的静态插件声明资产与全部既有命令行操作习惯。
2. **零场外反重力请求，严守合规红线**：彻底删除云端配额模块、登录凭据提取与云端鉴权诊断功能，杜绝任何向反重力或模型厂商服务端主动发起场外请求的行为；**模型配额**、套餐等级与账户标识完全消费宿主通过标准输入合法传入的数据。与反重力服务端无关的 GitHub 新版本检查提示及手动升级能力予以保留。
3. **统一计费口径、自动重扫建账与高内聚解耦架构**：保持“**状态栏**极简聚焦当前窗口核心指标与汇总金额、**网页看板**展开查看**任务树**下子代理消费明细”的交互分工不变，将底层字数与费用计算收口为全局唯一公式。升级时仅继承用户已保存的个性化设置，历史消费与今日/近七日花费直接通过重新扫描宿主原始对话记录（含命令行端与编辑器端）自动重建统一**账本**。代码内部按单一变化原因划分为高内聚深模块，模块间仅通过纯数据值对象单向通信。
4. **无感在线的网页看板体验**：保留浏览器独立小窗模式与系统桌面快捷图标，重构后台保活机制——只要用户的**网页看板**页面尚未关闭（即使长期最小化或处于后台标签页），后台服务均保持在线不断连；仅在所有页面真正关闭后自动回收退出。

## User Stories

1. 作为一名终端用户，我希望无需在电脑上安装任何脚本运行时或外部数据库命令行工具即可通过一键脚本完成安装，以便开箱即用。
2. 作为一名老版本Linux服务器用户，我希望下载到的预编译二进制完全静态自包含，以便在较旧系统库环境下也能直接运行而不报动态库缺失错误。
3. 作为一名终端用户，我希望每次模型回复后**状态栏**能在极短时间内完成刷新，以便日常高频对话毫无卡顿感。
4. 作为一名关注账号安全的用户，我希望工具绝不在宿主外部读取我的登录令牌或向反重力服务器主动发送任何请求，以便彻底杜绝违反服务条款导致账号封禁的风险。
5. 作为一名终端用户，我希望**状态栏**首行清晰展示当前使用的模型名称、推理强度、套餐徽章、当前工作目录及版本分支信息，以便一眼掌握当前会话环境。
6. 作为一名项目开发者，我希望**状态栏**能够显示当前工作区识别到的规则文档数量与已挂载工具服务数量，以便确认智能体上下文配置是否生效。
7. 作为一名终端用户，我希望看到直观的上下文进度条与已用百分比，并基于服务端实际的**上下文压缩**上限（而非仅看模型标称物理上限）计算水位，以便提前预判何时触发**上下文压缩**。
8. 作为一名长对话用户，我希望在发生**上下文压缩**后，**状态栏**能正确重置当前轮活跃上下文计数并保留历史峰值水位标记，以便区分压缩前后的上下文消耗。
9. 作为一名终端用户，我希望看到当前轮次的缓存命中率与读写字数统计，以便评估提示词缓存复用效率。
10. 作为一名多智能体调度用户，我希望在开启子代理或蜂群协作时，**状态栏**保持极简版面（不刷屏罗列全部子代理），但其显示的当前会话汇总花费已完整包含整棵**任务树**内主对话与所有子代理的消费，以便在不牺牲界面整洁度的前提下掌握真实总开销。
11. 作为一名多智能体调度用户，我希望**状态栏**能紧凑展示近期活跃子代理模型的生成速率摘要（并在闲置超时后自动隐去），以便了解后台并行执行面的响应表现。
12. 作为一名成本敏感用户，我希望**状态栏**同时展示今日累计花费与滚动近七日累计花费，且在会话发生**上下文压缩**或重置时不会倒扣已产生的今日花费，以便准确控制日常预算。
13. 作为一名终端用户，我希望**状态栏**显示的汇总金额与打开**网页看板**查看到的同一**任务树**总金额基于完全一致的系统提示词、缓存及阶梯费率公式计算，以便两边账目严丝合缝不再打架。
14. 作为一名终端用户，我希望通过宿主标准输入传入的**模型配额**数据，在**状态栏**查看厂商级 5 小时窗口与周窗口的剩余额度百分比、进度条及重置倒计时，以便合理安排高负载任务。
15. 作为一名偏好精简界面的用户，我希望能在“配额表格”与“紧凑配额单行”或“隐藏配额”模式之间自由切换，以便匹配个人阅读习惯。
16. 作为一名分屏或窄窗口用户，我希望当终端列宽收窄时，**状态栏**能按优先级自动逐级精简次要信息、绝不产生错乱折行或转义符截断乱码，以便在小窗口下依然保持清晰可读。
17. 作为一名多语言或受限终端用户，我希望工具能自动识别系统语言（中/英文）与终端字符集能力（Unicode 图标或纯 ASCII 字符降级），并支持手动覆盖，以便在 Windows 传统终端或远程会话中均不出现乱码方块。
18. 作为一名从旧版升级的用户，我希望升级后原有的主题配色、语言、显示开关与告警阈值等个性化设置自动保留生效，无需重新配置。
19. 作为一名从旧版升级或首次安装的用户，我希望程序能自动扫描本机已有的命令行端与编辑器端原始对话记录来建立完整的历史**账本**，以便无需迁移旧版缓存文件也能立即查看过往消费曲线。
20. 作为一名同时使用命令行与集成开发环境的用户，我希望**账本**能自动合并采集两端的历史对话并标记来源，以便全面统计我在所有入口的总用量。
21. 作为一名终端重度用户，我希望执行统计子命令即可直接在终端内查看按时间范围汇总的模型用量与花费报表，以便不打开浏览器也能快速查账。
22. 作为一名普通用户，我希望执行配置子命令后能进入交互式终端向导，用方向键或快捷键实时切换主题、面板样式、语言与开关并即时看到**状态栏**动态预览效果，保存后原子落盘，以便零门槛完成个性化定制。
23. 作为一名智能体用户，我希望继续通过对话要求智能体调整**状态栏**配置，且底层配置结构与字段语义保持向后兼容，以便既有的配置技能无缝工作。
24. 作为一名需要深度复盘的用户，我希望执行看板子命令后自动在本地回环地址启动服务，并以浏览器独立小窗模式（或默认浏览器标签页）打开**网页看板**，以便可视化浏览交互式图表。
25. 作为一名需要深度复盘的用户，我希望在**网页看板**中按时间范围（今日、24小时、7天、30天、本月、全部或自定义日期）、时间粒度（小时、天、周）、数据来源（全部、命令行、编辑器）、工作区及模型维度自由筛选趋势图与排行榜，以便定位高消耗来源。
26. 作为一名多智能体调度用户，我希望在**网页看板**的会话列表中看到按**任务树**归拢的总花费，并能点击展开任意一条**任务树**查看其下每个子代理**单窗对话**的模型、字数、速率与独立花费明细，以便做精细的成本归因。
27. 作为一名数据分析用户，我希望从**网页看板**一键导出当前筛选条件下的时间序列、模型分布或会话明细数据（CSV 或 JSON 格式），以便在外部表格工具中做二次归档。
28. 作为一名日常办公用户，我希望将**网页看板**最小化或切到后台标签页工作数小时后再切回来时，页面依然保持在线、点击筛选立即响应而不会断连失效；只有当我真正关闭页面窗口后后台进程才自动退出释放内存，以便省去反复重开命令的麻烦。
29. 作为一名桌面用户，我希望按需在系统桌面或应用启动菜单生成（或移除）带有专属标识的**网页看板**快捷启动图标，以便像本地桌面应用一样随时点开查账。
30. 作为一名关注版本迭代的用户，我希望当远端 GitHub 仓库发布新版本时，后台按日低频检查并在**状态栏**给出安静的版本更新提示（不自动后台静默替换正在运行的程序），以便我自主决定升级时机。
31. 作为一名用户，我希望在手动执行升级子命令时，程序自动拉取匹配当前操作系统与芯片架构的发布包、完成完整性哈希校验并安全替换旧二进制（含 Windows 运行中可执行文件的改名替换），以便一行命令完成安全升级。
32. 作为一名准备停用工具的用户，我希望执行卸载命令时能够干净移除宿主**状态栏**注册项、命令行入口与带有专属指纹的快捷图标，且默认保留我的历史**账本**数据（仅在显式指定彻底清除参数时才删除**账本**），以便防止误删珍贵历史统计记录。
33. 作为一名终端用户，我希望无论遇到标准输入为空、输入格式残缺、缓存损坏还是宿主正在高频写入对话数据库的情况，**状态栏**进程都能在严格超时上限内优雅降级输出并以零退出码结束，绝不锁死宿主数据库或阻塞正常对话。

## Implementation Decisions

- **单一原生二进制与分层职责架构**
  - 本地全部能力（**状态栏**主路径、子命令分发、历史摄取、**账本**存储、交互向导、**网页看板**服务端、安装卸载与自更新）编译为单一静态链接的 Rust 可执行文件，对外同时提供完整名与简写命令入口。
  - 代码库组织为单一核心库加极薄命令行入口，内部按“单一变化原因”划分为八个高内聚深模块：`domain`（领域值类型与唯一计费/配额计算）、`ingest`（宿主数据只读摄取）、`ledger`（统一持久化**账本**）、`render`（纯函数终端排版）、`config`（配置管理与交互向导）、`dashboard`（本地回环服务与保活控制）、`ops`（安装卸载与 GitHub 更新管理）及 `platform`（操作系统底层差异封装）。
  - 模块拆分以职责内聚为唯一标准，不设机械的单文件行数上限；模块间严格遵循单向无环依赖，仅通过 `domain` 定义的不可变或纯值数据结构传递信息，严禁跨模块传递数据库连接句柄、文件描述符或内部缓存状态。
  - `domain` 与 `render` 保持 100% 纯内存计算（零文件读写、零网络请求、零子进程调用、零隐式系统时钟读取），所有外部时间与终端能力均通过参数显式传入。

- **合规边界与模型配额处理**
  - 物理移除全部云端配额拉取、系统钥匙串/本地登录令牌读取以及云端鉴权诊断子命令，运行期绝不向反重力或模型厂商服务端发起任何场外请求。
  - **模型配额**模块仅解析宿主通过标准输入传入的厂商级窗口数据（5 小时窗口与周窗口剩余比例及重置时刻），保留表格模式与紧凑单行汇总模式；原依赖私有云端接口的单模型细分配额展示模式退役（若旧配置残留该枚举值，自动平滑回退至表格模式）。
  - 套餐等级与用户标识仅消费宿主标准输入字段，缺省时按默认占位逻辑展示，不再翻找宿主本地认证文件。

- **无锁只读宿主数据摄取（`ingest`）**
  - 统一收口全仓对宿主对话日志、对话 SQLite 数据库与工作区元数据的只读访问，外部模块仅通过摄取器公开门面获取当前实时状态快照或增量对话切片。
  - 读取宿主对话 SQLite 数据库时执行严格防锁冲突策略：若检测到非空预写日志（WAL）或活跃写入迹象，必须连同主库及伴生日志/共享内存文件复制到系统临时目录后再以只读模式查询；若为静态归档库，则以只读不可变（immutable）模式打开，确保对宿主原目录零字节写入、零共享内存锁干扰。
  - 宿主数据库中的二进制元数据通过模块内部私有的轻量级变长整数与线格式解析器解码，提取**上下文压缩**上限、系统提示词与输入输出字数、流式生成耗时、首字延迟及**任务树**父子血缘关系（主对话标识、父级标识与当前**单窗对话**标识），外部模块不感知底层二进制编码细节。
  - 对话事件日志采用基于文件标识与头部哈希校验的字节偏移增量扫描，支持大体积完整日志的条件回查与末尾窗口扫描，准确识别用户轮次、**上下文压缩**检查点事件以及子代理/蜂群成员的最近速率状态。
  - 工作区分支名称优先通过纯文件方式直接解析本地版本库头部引用以消除高频子进程开销，仅在复杂工作树结构下带超时回退调用本地版本控制命令；纯离线统计工作区规则文档与工具配置数量。

- **统一计费口径与单一 SQLite 账本（`domain` + `ledger`）**
  - 在 `domain` 内确立全局唯一的字数归一化与费用计算函数，消除旧版多处算账不一致的问题：明确区分各模型家族原始输入字数是否已包含缓存读写字数，统一将底层系统提示词字数纳入输入计费基数，并统一执行长上下文阶梯定价与按路由类型过滤不采信的原生上报费用。
  - 废除旧版独立的每日花费文本文件、自定义自旋文件锁及纯文本降级账本，依托内嵌静态编译的 SQLite（启用 WAL 模式与忙等待超时），将长期遥测**账本**与今日/滚动近七日费用汇总统一收敛至 `ledger` 模块管理。
  - **状态栏**主路径按节流间隔增量同步当前活跃**单窗对话**及关联子代理，并从**账本**快速读取今日与近七日累计花费（遇到会话重置或**上下文压缩**导致单会话累计值回退时，仅推进增量游标而不倒扣历史已计入花费）。
  - 首次启动或执行全量同步时，`ledger` 自动遍历命令行端与编辑器端数据目录下的全部对话数据库完成建账，支持按**任务树**根节点归拢主对话与全部后代子代理**单窗对话**的汇总指标与独立明细。

- **状态栏排版与容错契约（`render` + 顶层入口）**
  - `render` 接收领域状态快照、显示配置与终端能力描述（列宽、字符集支持），输出完整的多行格式化文本；内置东亚宽字符与表情符号列宽精确计算、颜色转义序列安全截断以及窄终端多级字段优雅降级策略。
  - **状态栏**执行路径设置 1500 毫秒硬性总超时保护；全库禁止未受控恐慌（panic），任何输入残缺、文件并发占用或局部解析异常均降级渲染可用部分，将诊断信息安全追加至只写权限的错误日志（校验非符号链接），并始终以状态码 `0` 退出，绝不阻断宿主对话流程。

- **配置兼容与交互式终端向导（`config`）**
  - 配置加载按“内置默认值 → 全局用户配置文件 → 当前工作区配置文件 → 环境变量覆盖”顺序深度合并；反序列化对旧版遗留废弃字段（如云端配额开关与私有端点列表）做静默忽略，确保老用户配置文件无需修改即可直接加载，保存时采用临时文件加原子重命名防止并发截断。
  - 交互式向导接管原始终端输入模式，支持键盘导航修改主题、语言、配额样式、上下文水位告警阈值及各显示项开关，并在同一界面内直接调用 `render` 实时渲染**状态栏**预览。

- **网页看板、长效保活与桌面集成（`dashboard`）**
  - 服务端强制仅绑定本地回环地址 `127.0.0.1`（默认端口被占用时自动回退随机可用端口），严格校验请求头中的主机名与来源白名单，下发内容安全策略响应头；原有零外部依赖的单页前端资源在编译期静态内嵌进二进制，保持概览查询、手动同步、健康探测与 CSV/JSON 导出接口契约。
  - 保活与自动退出状态机重构为以“是否存在打开的页面实例”为准：页面打开期间通过不因窗口最小化或后台标签页隐藏而中断的保活连接/全状态心跳（配合页面关闭卸载信标）维持活跃会话计数；只要仍有任一页面未关闭（无论处于前台、后台标签还是最小化状态），服务端持续在线；当最后一个页面关闭且宽限窗口内无新连接恢复时，后台守护进程自动优雅退出并清理实例发现状态。
  - 保留单实例健康复用机制、主流浏览器无地址栏独立小窗探测启动以及三端系统级快捷方式（带专属指纹标识，卸载时仅清理匹配指纹的快捷方式）。

- **安装、卸载与 GitHub 版本管理（`ops`）**
  - 安装器安全读写宿主设置文件中的**状态栏**命令配置（遇到损坏配置自动备份后再修复），并将命令行入口部署至用户独立可执行目录，不在反重力宿主自有安装目录内注入未签名脚本。
  - 保留低频（24 小时周期）异步后台检查 GitHub 仓库最新发布版本并更新本地状态提示的能力；手动执行升级命令时，从可配置的远端发布源下载当前平台与架构对应的压缩包及校验文件，通过 SHA-256 完整性校验后完成原子替换（Windows 下通过重命名当前运行中可执行文件实现热替换）。
  - 分发流水线构建五大目标平台预编译产物，移除旧版包管理器清单与脚本拉取引导器。

## Testing Decisions

- **什么是好测试**
  - 测试只针对对外可观测的行为（标准输出文本、退出码、生成的数据库查询结果、本地回环 HTTP 响应及目标目录文件状态）进行断言，绝不窥探模块私有状态、内部缓存结构或具体实现步骤；重构模块内部实现时无需修改既有测试。
  - 遵循仓库禁止对外部服务使用模拟替身（Mock）的工程规范，不向业务代码注入仅供测试使用的内部回调钩子。

- **被测接缝与模块覆盖**
  - **主接缝（既有最高接缝：二进制进程入口 + 环境变量隔离临时目录）**：
    - 通过环境变量将命令行端数据目录、编辑器端数据目录与全局配置目录重定向至测试用例独占的真实临时目录，放入构造或录制好的对话事件日志与 SQLite 对话数据库样本，向二进制喂入标准输入 JSON，直接断言标准输出的**状态栏**文本、退出码以及统一**账本**中的统计结果。
    - 在同仓迁移阶段，构建双端黄金样本对拍测试：将同一批真实形态的对话样本（覆盖普通单轮、多轮**上下文压缩**、含子代理的**任务树**、窄终端列宽、标准输入缺失/损坏、多种**模型配额**组合）同时输入现行脚本运行时与新版 Rust 二进制，验证除明确纠偏的计费公式差异外输出行为一致。
    - 针对**网页看板**，在测试中绑定 `127.0.0.1:0` 随机端口启动真实服务进程，发送真实本地 HTTP 请求验证筛选聚合、**任务树**子代理展开明细、CSV/JSON 导出、非法来源拦截（403），以及“后台隐藏不断连、关闭连接后自动退出”的完整生命周期。
    - 针对版本检查与手动自更新，沿用既有环境变量将发布源地址指向测试进程内启动的本地 `127.0.0.1` 静态文件 HTTP 服务，端到端验证版本比对、压缩包下载、SHA-256 校验失败拦截与校验通过后的二进制替换。
    - 针对安装与卸载，在隔离临时目录下验证宿主设置文件合并备份、快捷方式指纹校验清理以及默认保留**账本**与显式清除**账本**的行为。
  - **纯内存公开函数边界补充**：
    - 仅针对零 I/O 的 `domain`（各模型家族字数归一化、阶梯费率、临界**模型配额**窗口选取）与 `render`（宽字符混合截断、极端列宽降级）公开入口编写表驱动纯值输入输出断言，高效穷举数值边界。

- **仓库既有测试先例（Prior Art）**
  - 沿用仓库现有端到端显示与打包验证套件中“在完全隔离的沙盒数据目录下执行真实安装、喂入真实标准输入样本校验渲染行及启动本地临时 HTTP 服务测试分发包”的黑盒验收思路。
  - 沿用现有空标准输入/超时黑盒进程测试以及契约一致性测试中通过命令行退出码与标准输出文本验证外部契约的模式，淘汰原直接导入脚本内部私有函数并注入模拟依赖的白盒单测写法。

## Out of Scope

- 向反重力或任何模型厂商服务端主动发起外部网络请求、提取系统密码箱/本地登录令牌、逐模型私有云端配额展示模式以及云端鉴权诊断功能。
- 对旧版遗留的独立每日花费文本文件、纯文本降级账本及各类旧版解析/速率缓存文件编写格式兼容或数据迁移代码（统一通过重扫宿主原始对话记录重建）。
- 继续维护前端/脚本生态的包管理器发布渠道（移除 `npm` 包形态），或支持 Windows ARM64 及 32 位老旧硬件架构。
- 使用 WebAssembly 或引入第三方前端框架/外部 CDN 重写**网页看板**的浏览器端界面。
- 未经用户手动执行升级命令而自动在后台静默下载替换正在运行的程序文件。

## Further Notes

- **平滑切流与发布门槛**：在当前仓库内并存开发期间，现行脚本实现保留作为对拍基准；必须同时满足“黄金样本双端对拍通过、五大目标平台编译与自动化测试全绿、本机真实替换试用验证无误”三项门槛后，再一次性清理全部旧版脚本运行时文件与包清单，正式切流发布 `v2.0.0`。
- **架构防腐红线**：全库启用编译器静态检查，禁止在库代码中使用未处理的解包恐慌（`unwrap` / `expect`）；跨平台系统调用严格收口于 `platform` 模块内，禁止在领域、摄取、**账本**或渲染层散落操作系统条件编译分支。
