# 采用薄前端状态栏、统一单实例后台采集与纯内存 WAL 读取

为彻底消除每次**状态栏**刷新在宿主机内重复拉起重型 SQLite 拷库与账本写入所带来的冷启动抖动与磁盘 D 态阻塞风险，同时保持 ADR-0001 的单二进制零外部依赖形态与 ADR-0003 的深模块边界，我们决定将**状态栏**执行链路拆分为**薄前端**与**单实例常驻后台采集守护进程**两段：

1. **纯内存零落盘读取会话 `.db`**：`ingest` 模块读取宿主机**单窗对话**及子代理 `.db` 时，优先通过纯内存合并主库与 `-wal`（跳过不存在或缺失 `-shm` 带来的共享内存限制），直接调用 `sqlite3_deserialize` 挂载只读内存库，将每轮 3 遍（压缩限值、性能统计、**任务树**花费）读库合并为单次按文件路径与签名缓存的读取，零临时目录落盘、零修改宿主机数据库文件。
2. **双线程单写入者后台采集器（`collector`）**：将所有耗时 I/O（transcript 增量扫描、SQLite 遥测、**偏好配置**加载、**账本**同步与滚动花费落盘、后台同步/更新派发）收敛至单一常驻后台进程（独立无头模式 `--collector-bg`，并在**网页看板**后台运行 `dashboard --serve-background` 时由其同进程内嵌接管，共享 `KeepaliveState` 生命周期与活动保活）。IPC 监听线程与单线程串行 Worker 彻底隔离，按 `conversation_key` 防抖合并并发请求，确保即使 Worker 因底层磁盘进入不可中断等待，IPC 线程仍可在毫秒级响应 `Ping` / `Busy` / `Shutdown`。
3. **跨平台本地 IPC 与 `tmpfs` 预计算快照**：Unix 端使用受 `0600` 权限保护的 Unix Domain Socket（受 96 字节 `sun_path` 上限约束），Windows 端使用 `127.0.0.1` 随机端口加 128-bit 随机认证 Token；预计算快照与全局兜底快照原子写入运行期目录（Linux 生产优先 `$XDG_RUNTIME_DIR/agy-pulse/` 纯 `tmpfs`）。**薄前端**进程内严禁打开 SQLite 或写磁盘，收到 `Busy` 或超时时在纯内存中将实时 `stdin` 字段无损合并入缓存快照后即时渲染输出（保留 `AGY_PULSE_SYNC_MODE=1` 作为显式同步调试逃生路径）。
