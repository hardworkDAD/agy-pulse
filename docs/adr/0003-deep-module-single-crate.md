# 采用高内聚深模块与纯数据契约实现模块解耦

为根治 `v1` 时代多职责纠缠（解析、子进程、数据库与缓存耦合在一起）及计费/锁逻辑多处重复的问题，同时避免过度拆分为十余个微型子 Crate 产生胶水代码，我们决定将 `v2.0.0` 组织为单一 Cargo 库加极薄 CLI 外壳，按单一变化原因划分为高内聚深模块（`domain`、`render` 纯内存计算内核，以及 `ingest`、`ledger`、`config`、`dashboard`、`ops`、`platform`），不设机械的单文件行数上限。模块之间严格执行单向无环依赖，仅通过 `domain` 纯值数据结构通信（互不暴露底层文件或数据库连接句柄）以保证低耦合；原独立文件锁账本 `daily-cost.json` 合并入统一的 `ledger` SQLite WAL 存储，测试统一通过各模块公开接口执行。
